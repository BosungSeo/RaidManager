# 시스템 설계

상태: MVP 설계 기준안

## 시스템 구성

- 세션 시스템: 현재 게임 진행 상태를 생성하고 종료한다.
- 레이드 시스템: 레이드의 목표, 진행, 성공/실패를 관리한다.
- 팀 시스템: 캐릭터와 역할, 편성 상태를 관리한다.
- 자원 시스템: 체력, 재화, 장비 또는 기타 게임 자원을 관리한다.
- 저장 시스템: 게임 상태를 저장하고 불러온다.
- UI 시스템: 메뉴, 상태 정보, 선택지와 결과를 표시한다.
- 전투 시뮬레이션 시스템: 편성된 공격대와 던전 데이터를 바탕으로 자동 전투를 계산한다.
- 전투 기록 시스템: 피해, 회복, 스킬 사용, 사망과 주요 사건을 기록한다.
- 보상/성장 시스템: 전투 결과에 따라 캐릭터와 플레이어 진행 상태를 갱신한다.

현재 프로토타입에서는 전투 시뮬레이션, 전투 기록, UI 시스템을 우선 구현했다. 저장, 보상, 성장 시스템은 아직 연결하지 않았다.

## 상태 흐름

```text
Intro
  ↓
Main Menu
  ├─ New Game → Game Session
  └─ Load Game → Save Selection / Game Session

Game Session
  ↓
Raid Setup → Dungeon Select → Auto Battle → Battle Result
                                      ↑             ↓
                                      └── Strategy Update
```

현재 `Load Game`은 저장 데이터 없이 `NO SAVE DATA`를 표시하는 프로토타입 상태다.

## 데이터 원칙

- 게임 규칙과 진행 상태는 화면 코드와 분리한다.
- 화면(Scene)은 표시와 입력 전달을 담당하고, 시스템은 게임 상태를 변경한다.
- 저장 가능한 데이터는 명시적인 데이터 모델로 정의한다.
- 일시적인 UI 상태와 영구적인 게임 진행 상태를 구분한다.
- 밸런스 수치와 규칙은 화면 코드가 아닌 데이터 정의에 둔다.
- 동일한 입력과 전투 시드에서는 전투 결과를 재현할 수 있어야 한다.

## 핵심 데이터 모델 초안

```text
GameState
 ├─ PlayerProgress
 ├─ Roster
 ├─ RaidFormation
 ├─ DungeonDefinition
 └─ BattleResult
```

- `CharacterDefinition`: 역할, 기본 능력치, 보유 스킬
- `SkillDefinition`: 효과, 대상 규칙, 재사용 대기시간
- `ItemDefinition`: 능력치 또는 플레이 방식을 바꾸는 효과
- `RaidFormation`: 출전 캐릭터, 장착 스킬, 아이템, 전략 설정
- `DungeonDefinition`: 적 구성, 시간 제한, 핵심 기믹
- `BattleLog`: 시간순 사건과 캐릭터별 전투 통계
- `CombatCue`: 전투 사건과 `SkillType`을 화면 애니메이션으로 표현하기 위한 일회성 이벤트

## 자동 전투 규칙

- 실시간처럼 보이지만 시뮬레이션은 0.1초 고정 간격으로 갱신한다.
- 캐릭터는 공격과 스킬 재사용 대기시간을 가진다.
- Tank가 생존하면 적의 일반 공격을 우선해서 받으며 받는 피해가 감소한다.
- Healer는 체력 비율이 가장 낮은 생존 캐릭터를 회복한다.
- DPS와 Support는 고정된 스킬 재사용 대기시간과 역할별 효과로 행동한다.
- 던전은 40초 제한 시간과 하나의 핵심 전투 기믹을 가진다.
- 결과 화면은 단순한 `전투력 부족` 대신 수정 가능한 실패 원인을 제공한다.

현재 구현된 던전 기믹은 다음과 같다.

- `IRON COLOSSUS`: 일정 주기의 전역 폭발 피해. 보호막과 차단으로 대응한다.
- `SWARM NEST`: 일정 주기의 전역 피해와 다수 적 콘셉트. 광역 공격으로 대응한다.
- `RENEWING SLIME`: 일정 주기의 체력 회복. `SUNDER`의 회복 감소로 대응한다.

## 전투 연출 이벤트

시뮬레이터는 전투 결과와 별도로 화면이 재생할 `CombatCue`를 발행한다. Scene은 이 사건을 소비해 연출만 수행한다.

- `HIT`: 공격 이동, 투사체, 피격 섬광과 피해 숫자
- `HEAL`: 회복 링과 회복 숫자
- `SHIELD`: 캐릭터 주변 보호막 링
- `INTERRUPT`: 보스 기술 차단 연출
- `SUNDER`: 회복 감소 연출
- `WAVE`: 보스의 전역 공격 충격파

같은 `HIT`라도 기본 공격은 투사체로, `STRIKE`는 교차 참격으로, `CLEAVE`는 다중 참격으로, `INTERRUPT`는 번개 효과로, `SUNDER`는 중첩 링 효과로 표현한다. `HEAL`과 `GUARD`는 회복 문양과 보호막 링을 사용한다.

연출 이벤트는 게임 상태를 변경하지 않으며, 같은 전투 결과에 영향을 주지 않는다.

## 전투 결과 필수 기록

- 캐릭터별 피해량, 회복량, 받은 피해
- 사망 캐릭터와 사망 시점
- 스킬 사용 횟수와 주요 효과
- 보스 주요 기술의 발생 시각
- 승패, 전투 시간, 핵심 사건

## 저장 시스템 초안

- 저장 단위: 게임 세션 1개 또는 저장 슬롯 단위
- 저장 시점: 메뉴 선택, 레이드 종료, 명시적 저장 요청
- 저장 형식: 미정
- 저장 위치: 플랫폼별 앱 저장 공간
- 예외 처리: 손상되거나 존재하지 않는 저장 파일은 안전하게 실패 처리

MVP에서는 저장보다 전투 시뮬레이션과 결과 분석을 우선한다. 저장 시스템은 핵심 루프가 검증된 뒤 연결한다.

## 시스템 설계 시 확인할 것

- 시스템 간 의존 방향
- 한 프레임 안에서 상태가 여러 번 변경되는지 여부
- 재시작 후 복구해야 하는 데이터
- Android와 데스크톱에서 동일하게 동작해야 하는 부분
