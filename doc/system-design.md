# 시스템 설계

상태: 초안

## 시스템 구성

- 세션 시스템: 현재 게임 진행 상태를 생성하고 종료한다.
- 레이드 시스템: 레이드의 목표, 진행, 성공/실패를 관리한다.
- 팀 시스템: 캐릭터와 역할, 편성 상태를 관리한다.
- 자원 시스템: 체력, 재화, 장비 또는 기타 게임 자원을 관리한다.
- 저장 시스템: 게임 상태를 저장하고 불러온다.
- UI 시스템: 메뉴, 상태 정보, 선택지와 결과를 표시한다.

## 상태 흐름

```text
Intro
  ↓
Main Menu
  ├─ New Game → Game Session
  └─ Load Game → Save Selection / Game Session
```

현재 `Load Game`은 저장 데이터 없이 `NO SAVE DATA`를 표시하는 프로토타입 상태다.

## 데이터 원칙

- 게임 규칙과 진행 상태는 화면 코드와 분리한다.
- 화면(Scene)은 표시와 입력 전달을 담당하고, 시스템은 게임 상태를 변경한다.
- 저장 가능한 데이터는 명시적인 데이터 모델로 정의한다.
- 일시적인 UI 상태와 영구적인 게임 진행 상태를 구분한다.

## 저장 시스템 초안

- 저장 단위: 게임 세션 1개 또는 저장 슬롯 단위
- 저장 시점: 메뉴 선택, 레이드 종료, 명시적 저장 요청
- 저장 형식: 미정
- 저장 위치: 플랫폼별 앱 저장 공간
- 예외 처리: 손상되거나 존재하지 않는 저장 파일은 안전하게 실패 처리

## 시스템 설계 시 확인할 것

- 시스템 간 의존 방향
- 한 프레임 안에서 상태가 여러 번 변경되는지 여부
- 재시작 후 복구해야 하는 데이터
- Android와 데스크톱에서 동일하게 동작해야 하는 부분
