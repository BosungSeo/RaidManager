# 게임 프로젝트 통합 기획서

상태: MVP 기준 기획안

이 문서는 RaidManager의 기준 기획이다. 구현 시에는 `의미 있는 조합 선택 → 자동 전투 → 실패 원인 분석 → 전략 수정`의 핵심 루프를 가장 먼저 검증한다.

## 1. 한 문장 정의

> 내가 직접 싸우는 게임이 아니라, 내가 만든 공격대가 싸우는 자동 전투 기반 공격대 운영 게임.

## 2. 핵심 경험

플레이어는 캐릭터 하나를 직접 조작하는 대신 공격대 전체를 설계하고, 자동 전투의 결과를 분석하여 다음 전략을 수정한다.

```text
공대 구성 → 캐릭터 세팅 → 던전 선택 → 자동 전투
→ 결과 분석 → 보상과 성장 → 전략 수정 → 재도전
```

## 3. 핵심 재미와 게임 이론

| 재미 요소 | 플레이 경험 | 설계 조건 |
|---|---|---|
| 전략적 의사결정 | 누구를 어떤 역할로 편성할지 고민 | 선택마다 장단점이 있어야 함 |
| 결과 예측 | 현재 조합의 성공 가능성을 가늠 | 전투 규칙과 위험 신호가 읽혀야 함 |
| 실패 분석 | 패배 원인을 찾아 전략을 수정 | 전투 기록이 원인과 결과를 보여줘야 함 |
| 성장 피드백 | 과거에 실패한 던전을 돌파 | 수치 성장과 전략 성장이 함께 작동해야 함 |

핵심 설계 원칙은 **의미 있는 선택**이다. 하나의 고정 정답보다 던전, 적, 아군 조합에 따라 가치가 달라지는 선택을 제공한다.

- 딜러를 늘리면 제한 시간 대응력은 높지만 생존력이 낮아진다.
- 안정적인 조합은 성공 확률이 높지만 전투 시간이 길어진다.
- 특정 직업은 모든 상황의 상위 호환이 아니라 특정 문제에 대한 해법이 된다.
- 실패는 막힘이 아니라 다음 실험에 필요한 정보를 제공한다.

## 4. 공격대 시스템

여러 보유 캐릭터 중 일부를 선택하여 공격대를 구성한다. 공격대 규모 증가는 단순한 슬롯 해제가 아니라 전략적 복잡도의 성장이다.

| 진행 단계 | 최대 출전 인원 | 상태 |
|---|---:|---|
| 초기 | 3명 | 확정 방향 |
| 1단계 성장 | 4명 | 확정 방향 |
| 2단계 성장 | 5명 | 확정 방향 |
| 후반 | 6명 | 확정 방향 |

공대 단계는 일반 경험치만으로 자동 상승하지 않는다. 조건을 충족하면 승급전이 열리고, 이를 클리어하면 인원과 신규 콘텐츠가 해금된다.

## 5. 성장 구조

| 성장 축 | 의미 |
|---|---|
| 플레이어 레벨 | 게임 전체 진행 수준 |
| 공대 레벨 | 출전 인원과 콘텐츠 단계 |
| 캐릭터 레벨 | 개별 캐릭터의 전투 성장 |
| 빌드 성장 | 스킬과 아이템 조합의 확장 |
| 플레이어 숙련 | 규칙 이해와 판단 능력의 향상 |

기존 캐릭터는 플레이어 진행에 맞춰 자연스럽게 성장시켜 반복 육성 부담을 줄인다. 신규 캐릭터는 현재 진행도에 따른 최소 성장 보정을 제공해 즉시 새로운 전략을 시험할 수 있게 한다. 정확한 보정 공식은 미정이다.

기존 캐릭터는 안정적인 투자 가치를, 신규 캐릭터는 새로운 전략 선택지를 제공한다. 신규 캐릭터가 기존 캐릭터의 단순 상위 호환이 되어서는 안 된다.

## 6. 역할과 직업

| 역할 | 전투 문제 해결 방식 |
|---|---|
| Tank | 피해를 받아내고 아군을 보호 |
| Healer | 피해를 복구하고 생존을 유지 |
| DPS | 적을 제거하고 시간 압박을 해결 |
| Support | 버프, 디버프, 차단, 전투 제어 |

같은 역할 안에서도 다른 판단과 조합을 만들어야 한다.

| 역할 | 직업 방향 예시 |
|---|---|
| Tank | 방어형, 회피형, 반격형, 보호형 |
| DPS | 지속형, 폭발형, 조건형, 광역형, 처형형 |
| Healer | 단일 집중형, 광역형, 지속 회복형, 예방형 |
| Support | 강화형, 약화형, 차단형, 행동 제어형 |

직업의 가치는 `직업 × 던전 × 적 × 다른 공대원`의 관계에서 결정된다.

## 7. 스킬과 아이템

캐릭터는 보유 스킬 전부가 아니라 일부만 전투에 장착한다. 초기 방향은 보유 6개 중 3개 선택이며, 정확한 개수는 프로토타입에서 검증한다.

```text
캐릭터 + 장착 스킬 + 아이템 = 실제 전투 빌드
```

아이템은 단순 능력치 상승보다 플레이 방식을 바꾸는 효과를 우선한다.

| 단순 수치 효과 | 빌드 변화 효과 |
|---|---|
| 치명타 확률 +10% | 치명타 시 재사용 대기시간 1초 감소 |
| 공격력 +20 | 보호막 보유 중 공격이 광역 피해로 전환 |

## 8. 던전 설계

던전은 적의 능력치만 높이는 관문이 아니라 공격대 구성을 다시 고민하게 만드는 전략적 문제다.

| 던전 특징 | 가능한 대응 |
|---|---|
| 강한 광역 공격 | 광역 회복, 보호막, 피해 감소 |
| 다수의 잡몹 | 광역 피해, 행동 제어 |
| 보스 폭발 피해 | 방어기, 보호, 타이밍 대응 |
| 적의 회복 | 차단, 회복 감소 |
| 높은 방어력 | 방어 감소, 방어 무시 |
| 지속 피해 | 정화, 지속 회복 |

한 가지 대응만 강제하지 않고 최소 두 가지 이상의 유효한 해법을 지향한다.

## 9. 자동 전투와 전투 기록

플레이어의 주요 개입은 전투 전에 이루어진다.

| 전투 전 | 전투 중 | 전투 후 |
|---|---|---|
| 편성, 배치, 스킬, 아이템, 전략 설정 | 자동 실행 및 선택적 관전 | 결과와 실패 원인 분석 |

관전하지 않아도 전투 결과와 주요 사건을 기록한다.

- 피해량, 회복량, 받은 피해
- 사망 원인과 시점
- 스킬 사용 횟수
- 보스 주요 기술 타임라인
- 승패를 가른 핵심 사건

`전투력 부족` 같은 단일 메시지는 피한다. 플레이어가 다음 시도에서 바꿀 수 있는 원인을 보여준다.

## 10. 보상 원칙

| 보상 | 목적 |
|---|---|
| 장비 | 기존 빌드 강화 또는 플레이 방식 변화 |
| 성장 재화 | 캐릭터와 시스템 성장 |
| 스킬 재화 | 선택지 확장 |
| 캐릭터 관련 보상 | 새로운 조합 해금 |
| 특수 아이템 | 특정 던전이나 빌드의 대안 제공 |
| 콘텐츠 해금 | 진행감과 새로운 문제 제공 |

보상은 능력치 상승뿐 아니라 새로운 전략을 열어야 한다.

## 11. 전체 진행

| 구간 | 주요 경험 |
|---|---|
| 초기 | 3인 공격대, 기본 역할 학습, 첫 빌드 형성 |
| 중기 | 승급전, 4인 공격대, 복합 던전 기믹 |
| 후기 | 5~6인 공격대, 정교한 시너지, 빌드 최적화 |

## 12. 기술 방향

| 항목 | 현재 방향 |
|---|---|
| 초기 플랫폼 | Android |
| 언어 | Kotlin |
| 프레임워크 | libGDX 프로토타입 적용 |
| 구조 원칙 | 화면과 게임 로직 분리, 데이터 중심 설계 |
| 개발 방식 | 작은 기능 단위 구현 → 실행 확인 → 다음 기능 |

libGDX는 현재 전투 프로토타입의 공통 실행 환경으로 적용했다. 전투 계산은 순수 Kotlin으로 분리하고, 화면은 전투 사건을 받아 애니메이션을 재생한다.

현재 프로토타입의 전투 연출 목표는 실제 아트 리소스 없이도 공격대 운영의 관전성을 확인하는 것이다. 캐릭터 이동, 보스 모션, 피격·회복·보호막·충격파를 전투 기록과 연결하고, 이후 스프라이트와 파티클 리소스로 교체한다.

## 13. MVP 범위

| 항목 | 목표 범위 |
|---|---:|
| 보유 캐릭터 | 6명 |
| 출전 인원 | 3명 |
| 역할/직업 | 4종 |
| 스킬 | 캐릭터당 2~3개 |
| 아이템 | 약 10개 |
| 던전 | 3개 |
| 보스 | 1~2종 |
| 전투 | 자동 전투 |
| 분석 | 전투 로그와 핵심 통계 |
| 성장 | 핵심 검증에 필요한 최소 범위 |

MVP의 목적은 콘텐츠 양이 아니라 다음 가설의 검증이다.

1. 공대 조합을 바꾸는 과정이 재미있는가?
2. 전투 결과만 보고도 실패 원인을 이해할 수 있는가?
3. 전략을 수정해 다시 도전하고 싶은가?
4. 새 캐릭터나 아이템이 새로운 조합 실험을 유도하는가?

## 14. 미정 사항

| 우선순위 | 항목 | 결정할 질문 |
|---:|---|---|
| 1 | 전투 규칙 | 시간, 턴/실시간, 행동 순서, 승패 조건은 무엇인가? |
| 2 | 초기 직업 | MVP 4종이 각각 어떤 문제를 해결하는가? |
| 3 | 전투 AI | 대상과 스킬 사용 우선순위를 어떻게 설정하는가? |
| 4 | 배치와 어그로 | 전열/후열과 공격 대상 규칙이 필요한가? |
| 5 | 던전 | MVP 3개가 어떤 서로 다른 조합을 요구하는가? |
| 6 | 성장 | 신규 캐릭터 보정과 경험치 공식은 무엇인가? |
| 7 | 아이템 | 슬롯, 등급, 획득 방식은 무엇인가? |
| 8 | 메타게임 | 모집, 반복 플레이, 엔드 콘텐츠는 무엇인가? |

## 15. 변경 원칙

- 재미 검증 결과가 기존 설계보다 우선한다.
- 확정된 규칙과 아이디어 후보를 구분한다.
- 새 시스템은 핵심 루프를 강화할 때만 추가한다.
- 밸런스 수치는 데이터로 분리해 빠르게 실험할 수 있게 한다.
